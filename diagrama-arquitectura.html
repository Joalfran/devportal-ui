DevPortal UI — Arquitectura y Flujo de Datos

Diagrama de referencia visual del proyecto devportal-ui (React + Vite + TypeScript + Tailwind). Archivo único e independiente, sin dependencias externas: no modifica ni afecta ningún archivo del proyecto.

1 Estructura del proyecto

Archivos relevantes dentro de devportal-ui/ (se omiten carpetas de configuración/build).

devportal-ui/
├── index.html punto de entrada HTML
├── package.json, vite.config.ts, tsconfig.json
└── src/
├── main.tsx monta la app en el DOM
├── App.tsx estado global + layout raíz
├── types.ts (tipos: ActiveView, tokens, Notification...)
├── index.css
└── components/
├── Header.tsx buscador, tema, idioma, carrito

├── ComponentsView.tsx pantalla "Components"
├── TemplatesView.tsx pantalla "Templates"
└── Footer.tsx

2 Árbol de componentes

Todo el estado vive en App.tsx y se reparte hacia abajo mediante props. No hay backend: es una app 100% cliente con datos de ejemplo (mock) definidos dentro de cada componente.

App.tsx activeView · activeSubSection · searchQuery · cartCount · notifications[]
Headerbúsqueda, tema, idioma, carrito
Sidebarnavegación principal + subsecciones
‹main› (vista activa)renderiza 1 de 3 pantallas
Toast containerlista de notifications[]
Footerenlaces estáticos
FoundationsViewgrid, spacing, colores, tipografía
ComponentsViewbuttons, inputs, badges, modals
TemplatesViewproducto, perfil, métricas live

3 Flujo de datos entre pantallas / componentes

Todos los datos son de ejemplo (arrays hardcodeados en cada vista: tokens de color, specs de producto, perfil "Adrián Guerrero", métricas simuladas con setInterval). No hay llamadas a red. Haz clic en cada flujo para expandirlo.

▶ Flujo 1 — Navegación entre pantallas Sidebar → App → Vista
1SidebarEl usuario hace clic en "Foundations / Components / Templates"
→
2setActiveView()Actualiza el estado activeView en App.tsx
→
3App.tsxRe-renderiza y decide qué vista mostrar en el <main>
→
4Vista activaSe monta Foundations / Components / Templates View
→
5addNotification()Se dispara un toast "Mostrando sección: …"
▶ Flujo 2 — Búsqueda global Header → App → Vista
1HeaderEl usuario escribe en el buscador (placeholder cambia según la vista)
→
2setSearchQuery()Actualiza searchQuery en App.tsx
→
3prop searchQuerySe pasa como prop a la vista activa (Foundations/Components/Templates)
→
4Filtro localCada vista filtra sus arrays de ejemplo (colores, componentes, plantillas) por coincidencia de texto
▶ Flujo 3 — Notificaciones (toasts) Cualquier vista → App → Toast
1Header / Sidebar / VistasCualquier acción (copiar color, cambiar tema, abrir modal, etc.) llama a addNotification(msg, tipo)
→
2App.tsxAgrega el mensaje al array notifications[]
→
3Toast containerRenderiza la lista de tarjetas flotantes (éxito / info / error)
→
4setTimeout 4.5sCada notificación se autoelimina del array (o el usuario la cierra con ×)
▶ Flujo 4 — Carrito de compras TemplatesView ↔ App ↔ Header
1TemplatesViewEl usuario pulsa "Añadir" en la tarjeta de producto (laptop de ejemplo)
→
2onAddToCart()Callback que incrementa cartCount en App.tsx
→
3HeaderMuestra el badge "Carrito (n)" recibido como prop
→
4onClearCart()Al hacer clic en el badge, vuelve cartCount a 0
→
5addNotification()Muestra el toast "Tu carrito ha sido vaciado"
